Add your tool, step by step

You need a GitHub account with write access to the repository (ask the maintainer to invite you), git, and Python 3 for the local server and the checker.

1Clone and branch

git clone https://github.com/bpashchenko12/internal-tools.git
cd internal-tools
git checkout -b tool/your-tool-id

2Copy the template

The id is lowercase with dashes, for example market-brief. It becomes the folder name and the URL.

cp -r tools/_template tools/your-tool-id

3Build your page

  • In tools/your-tool-id/index.html change the <title>, the data-title on #hub-bar and the content in <main class="page">.
  • Keep the gate.js line first in <head>. It is the shared login, so never write your own.
  • Put logic in app.js and styles in tool.css. Prefix your own class names with the tool id.
  • Build with the components shown further down this page before inventing anything new.

4Register the tool

Add an entry to tools.json, inside the tools array. This is what puts your app icon on the home screen. All fields are explained below.

{
  "id": "your-tool-id",
  "name": "Your Tool",
  "description": "One sentence, under 140 characters.",
  "category": "SEO & Marketing",
  "status": "prototype",
  "icon": "chart",
  "accent": "green",
  "owner": "Your name or team",
  "path": "tools/your-tool-id/"
}

5Run it locally

python3 -m http.server 8000

Open http://localhost:8000, log in with the shared password (ask the maintainer), and check that your icon appears and the tool opens. Opening the files directly with file:// does not work, because tools load their data with fetch.

6Run the checker

python3 scripts/check.py

It checks tools.json, that gate.js loads first, that you used tokens and no hex colours, that no text is under 12px, that no third-party scripts are loaded and that no credentials were pasted in. Fix every FAIL line. The same check runs on your pull request.

7Test properly

  • Click through every screen and every button.
  • Resize to about 390px wide. Nothing should scroll sideways except tables inside their own card.
  • Open the browser console. There must be no errors.

8Open a pull request

git add .
git commit -m "Add Your Tool"
git push -u origin tool/your-tool-id

Open the link GitHub prints, or the Pull requests tab, and fill in the checklist. Pushing straight to main is blocked. After review and merge the hub redeploys within about a minute and your tool appears on the home screen. Reload the live site and open it once to confirm.

tools.json fields

FieldWhat to put
idUnique, lowercase, dashes. Must match the folder name.
nameShort name shown under the app icon, ideally 1 to 3 words.
descriptionOne sentence about what it does and for whom. Under 140 characters.
categoryFree text, for example "SEO & Marketing". Reuse an existing one where it fits.
statusprototype (idea, may change), beta (usable, still evolving) or live (team relies on it). The home screen shows a badge for prototype and beta.
iconOne of the names in the picker below.
accentApp icon colour: green, blue, amber, purple, red or dark.
ownerPerson or team who maintains it. People ask them questions.
pathExactly tools/<id>/ with a trailing slash.
urlOptional. Use instead of path for a tool that already lives on its own site (https://). The icon opens it in the same tab; the browser back button returns to the hub.

Data and secrets

The repository and site are public. The password only hides the page, so treat every committed file as public.

  • Never put API keys, tokens, passwords or credentials in the repository or in browser code.
  • Do not call private or paid APIs from the browser. Collect data in a separate job (a script, a scheduled GitHub Action using repository secrets, or a notebook), sanitise it, and commit only the resulting JSON to tools/your-tool-id/data/.
  • Load it with a relative path, for example fetch('data/snapshot.json').
  • Do not commit raw exports, customer data or personal data.
  • Say in the interface when numbers are estimates or when a source is missing. Never invent numbers.
  • Escape any dynamic text with XMTools.esc before putting it into innerHTML, and do not load third-party scripts.

Updating or removing a tool

  • Update: use a new branch and pull request, as above. Refreshed data is just a new JSON file in your data/ folder.
  • Change status: edit status in tools.json as the tool matures.
  • Remove: delete the folder and its entry in tools.json in the same pull request.

Troubleshooting

ProblemFix
No icon on the home screenCheck tools.json is valid JSON (commas between entries) and run python3 scripts/check.py.
Home screen says it could not load tools.jsonStart the local server and open http://localhost:8000, not the file.
Blank page or login loopsThe gate.js path is wrong. In tools/<id>/index.html it must be ../../assets/js/gate.js.
Page has no stylingCheck ../../assets/css/xm.css is linked and the path is right.
An icon looks hugeGive the SVG an explicit width and height in your CSS.
The check fails on a colour or sizeReplace the hex colour with a var(--token). Use the --fs-* sizes, never under 12px.
Cannot pushAsk the maintainer for write access, and push a branch, not main.
Merged but not visibleWait a minute, check the Actions tab for a green deploy, then hard-reload the page.

Style rules

  • Use assets/css/xm.css only. Colours, radius, shadows and sizes come from var(--tokens). Never write a hex colour.
  • The font is Poppins. The smallest text is 12px (--fs-xs).
  • Primary actions are green .btn-primary, one per screen.
  • A page is .page plus .page-head (eyebrow, title, one line of context, optional action).
  • Your own CSS goes in tool.css, with class names prefixed by your tool id.
  • Green means good or brand, red means bad or risk, amber needs attention, blue is information.
